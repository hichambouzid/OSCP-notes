A hypothesis is not a finding. Do not treat a version match, a response code, or a directory relationship as proof of a security weakness by itself.

## Reproducibility record

For each completed authorized exercise, record the actual command, output, prerequisites, version and result in private notes. Record failures too. Use sanitized references if publishing a practice writeup; never publish exam material, credentials, hashes, private keys or proof values.

## Proof and report checklist

- [ ] Correct target and assigned objective.
- [ ] Appropriate interactive shell and identity confirmed.
- [ ] Original required proof file read with permitted command; target IP visible in screenshot.
- [ ] Proof submitted in control panel before exam ends (if applicable).
- [ ] Screenshot readable; original evidence kept private.
- [ ] Report steps and actual output are reproducible.
- [ ] Tool restrictions checked.
- [ ] Cleanup required by the applicable rules completed.
- [ ] Report package and submission verified using official instructions.

## Retrospective (practice only)

- What did I understand?
- What did I forget?
- What error wasted the most time?
- What command did I look up, and what does each option mean?
- Which assumption was wrong?
- Which concept should I study next?
- Can I repeat this independently?
